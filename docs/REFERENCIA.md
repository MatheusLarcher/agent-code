## scripts/

| Arquivo | Responsabilidade |
|---------|------------------|
| `scripts/make-icon.mjs` | Usa o **Playwright** (Chromium já instalado) para rasterizar `build/icon.svg` em `icon.png` (512) e `icon.ico` (256). Renderiza o SVG numa página com fundo transparente e tira screenshot (`omitBackground`); monta o `.ico` empacotando o PNG 256 num cabeçalho ICO de uma imagem. |
| `scripts/screenshot.mjs` | Gera o print do README (`docs/screenshot.png`): sobe o app via Playwright `_electron`, semeia uma conversa de exemplo, abre uma aba web num site real e captura a janela. |
| `scripts/ui-tab-test.mjs` | Smoke test do sistema de abas: abre o app, cria abas web, navega e troca entre elas, conferindo que cada aba mostra o site certo. |
| `scripts/stage-chromium.mjs` | Copia o Chromium do Playwright (e o `winldd`, opcional) para `out/ms-playwright/`, de onde o electron-builder o embute em `resources/ms-playwright` (em produção, `index.ts` aponta `PLAYWRIGHT_BROWSERS_PATH` para lá). Usa `chromium.executablePath()` para achar a revisão instalada; falha com instrução (`npx playwright install chromium`) se não existir, e é **ignorado fora do Windows**. Chamado por `npm run package:win`. |
| `scripts/build-windows-control.mjs` | `dotnet publish` do helper nativo do controle do Windows (`src/main/windowsControl/native`, .NET 8, `win-x64`, *self-contained*, single-file, sem símbolos) para `out/windows-control/`. Ignorado fora do Windows; sem o SDK .NET, erra com instrução. Chamado por `npm run dev`/`build` (`windows-control:build`). |
| `scripts/relaunch-agent-code.ps1` | **Reinicia o app quando o próprio agente precisa reiniciar** — ele roda DENTRO do app e não consegue se fechar e reabrir sozinho, então o script roda fora, num processo destacado. Sequência: **confere o guarda → espera 5 s → fecha → espera 5 s → reabre** (`-CloseDelay`/`-OpenDelay`). **Só reinicia se nenhum agente estiver ocupado**: quem responde isso é o app (`restart-guard.json`, ver abaixo), porque um script vê processos, nunca conversas. Estado ausente, ilegível ou com mais de `-MaxGuardAge` (15 s) = desconhecido = **não reinicia** (`exit 2`); agente ocupado = `exit 3`. `-Force` pula o guarda (uso manual do usuário). Fecha com `CloseMainWindow` antes de forçar, para o app salvar. A espera antes de reabrir existe porque o Electron usa **trava de instância única por `userData`** — reabrir com o antigo vivo faz o novo se ver como segunda instância e fechar na hora, sem erro visível. Registra tudo em `%TEMP%\agent-code-relaunch.log`: silêncio não é prova de que reabriu. Ver [ARQUITETURA.md](ARQUITETURA.md#reiniciar-o-app-pelo-agente). |
| `scripts/remote-download-harness.ts` | Sobe a **ponte LAN sozinha** (sem o app), servindo o cliente do celular em `/app` com uma conversa que já contém os dois caminhos de download (`Write` entregável + marcador `[[download:]]`) e os arquivos reais em disco. É como o download foi exercitado de ponta a ponta no app Android instalado, apontando o celular/emulador para `http://<host>:8765` com o token impresso no stdout. Bundlar com `esbuild` e rodar; não é usado pelo app. |
| `scripts/vigia-probe.ts` | **Prova de campo do vigia**: roda o prompt real contra o modelo real em dois casos opostos (premissa que só o usuário sabe → espera `ALERTA`; pedido fechado → espera `OK`) e imprime o veredito já passado pelo parser. Existe porque o teste unitário prova o *parser*, não a **qualidade do prompt** — e é ela que decide se o recurso vira aviso útil ou ruído. Bundlar com esbuild (`--external:@anthropic-ai/claude-agent-sdk`) e rodar; não é usado pelo app. Rode de novo sempre que mexer no `VIGIA_SYSTEM_PROMPT`. |
| `scripts/po-probe.ts` | **Prova de campo do PO**: roda o prompt real contra o modelo real em quatro casos e imprime as operações já passadas pelo parser e pelas barreiras. Existe pelo mesmo motivo do `vigia-probe.ts` — o teste unitário prova o parser, não a qualidade do prompt, e aqui é ela que decide se o quadro fica honesto. O caso que mais importa é "nada terminou": o PO tem de responder `OK`. Foi ele que pegou o PO criando um cartão **pendente** para uma ação **já executada** (`tsc --noEmit`), corrigido no prompt. Bundlar com esbuild e rodar; não é usado pelo app. Rode de novo sempre que mexer no `PO_SYSTEM_PROMPT`. |
| `scripts/android-probe.mjs` | Verifica o caminho do preview Android: abre a aba Android (conecta ao device/emulador), checa as linhas de progresso e captura a tela com a moldura. |
| `scripts/run-postgres-tests.mjs` | **`npm run test:pg`** — a suíte de integração do PostgreSQL num comando só: sobe `postgres:16-alpine` como `agent-code-pg-test` em `127.0.0.1:15432`, espera o banco **aceitar conexão de verdade** (driver `pg`, não `sleep`), roda os cinco arquivos com `--no-file-parallelism` e remove o container no `finally`. Três detalhes que o fazem valer: a remoção acontece **também quando o teste falha** (órfão segurando a porta faz a execução seguinte falhar sem motivo aparente) e um `docker rm --force` **na entrada** cobre o que `finally` não cobre (`kill -9`, reboot); o `finally` não toca em `process.exitCode`, então falha de teste continua propagando; e a porta default é **15432** porque a 55432 da doc antiga cai na faixa reservada do Windows (`netsh` reserva 55417-55516) e nem sobe. O argumento posicional do vitest é **regex**, não glob — os arquivos são listados do diretório, senão `postgres*.test.ts` não casaria o que a doc sugeria. |

## src/main — processo principal

| Arquivo | Responsabilidade |
|---------|------------------|
| `index.ts` | Cria o `BrowserWindow` (tamanho, ícone, title bar oculta + overlay, CSP via HTML), libera a permissão de **microfone** (`setPermissionRequestHandler`/`setPermissionCheckHandler` só para `media`), abre links externos no navegador do sistema, chama **`initStore()`** no `app.whenReady` (abre o SQLite da pasta de cache + migra o `settings.json` legado) e **registra todos os handlers IPC** (incl. `app:pick-file`, **`app:path-exists`** — guarda da pasta do projeto, `app:open-in-editor`, **`app:file-download`** — copia um entregável para Downloads e revela, **`openai:transcribe`/`openai:tts`** — voz (key lida da config), **`auth:status`/`auth:login`** — login do Claude com um clique, **`cache:get-info`/`cache:choose-dir`** — pasta de dados, `agent:dispose`, **`agent:refresh-usage`** — força um poll do uso da conta (5h/semana) numa sessão conectada, `browser:*`). Mantém `mainWindow`, um **`Map<convId, AgentSession>`** (sessões paralelas) e um **`Map<convId, BrowserController>`** + `activeConvId`. O `RemoteServer` recebe `loadToken`/`saveToken` (token fixo), `onInbound` carregando `images` e `transcribe`/`tts`/`voiceReady` (voz no celular). Mantém um `authLog()` de diagnóstico temporário (`<localDir>/logs/auth-debug.log`). No boot e ao trocar a pasta de dados, dispara `relocateLocalLeftovers()` em segundo plano. No **exe portátil** (`app.isPackaged`), aponta `PLAYWRIGHT_BROWSERS_PATH` para `resources/ms-playwright` — o Chromium embutido — quando a env ainda não está definida. Passa à `AgentSession` um `onTurnComplete` que **libera o lease** da conversa ao fim do turno (só se aquela sessão ainda for a registrada), e `agent:send` **readquire** o lease em vez de recusar com `LEASE_HELD_BY_OTHER_DEVICE`. O `emit` de cada sessão é o **tee de eventos** que alimenta `vigia.observe`, `board.observe` e `po.observe`, os três no mesmo tick. O fechamento de turno que o `board` enfileira espera pelo `po.settled` (ligado como `poSettled` na construção do `BoardService`); o que garante que haja análise a esperar é o registro **síncrono** feito por `Po.start`, e não a ordem das chamadas — a closure do `closeTurn` só chega ao `waitForPo` num microtask posterior, então a inversão das duas linhas seria indiferente. `agent:send` chama `vigia.noteUserMessage` e `po.noteUserMessage` (que também dispara a **abertura** do PO); `agent:dispose` limpa os três. |
| `openai.ts` | **Cliente de áudio da OpenAI** (voz no chat) — vive no main para a key nunca chegar ao renderer; usa `fetch`/`FormData`/`Blob` embutidos do Node. `transcribeAudio` (fala → texto, `gpt-4o-transcribe`, `language: 'pt'` + `prompt` de contexto pt-BR — segmentos curtos/ruidosos alucinavam outro alfabeto, ex. cirílico, mesmo com `language` setado) e `synthesizeSpeech` (texto → MP3, `gpt-4o-mini-tts`, instrução forçando pt-BR; a velocidade é aplicada no renderer via `playbackRate`). |
| `auth.ts` | Estado de autenticação do Claude: `isAuthenticated()` pergunta ao próprio CLI (`claude auth status --json`) — **não** lê `.credentials.json` porque no Windows o token fica no Credential Manager. Multiplataforma e autoritativo. |
| `login.ts` | **Login do Claude com um clique**: `runClaudeLogin(openUrl, log)` faz `spawn` de `claude auth login --claudeai`, **raspa a URL de OAuth do stdout** e a abre no navegador do sistema, confirma via `auth status` (poll/marker/exit/timeout 3 min). Um login por vez (`inFlight`). |
| `codexAuth.ts` | Login OAuth da assinatura ChatGPT para os modelos GPT do Codex: PKCE + callback loopback, tokens protegidos pelo `safeStorage`, refresh antecipado e status/logout para Configurações. Não usa a API key de voz nem uma API key faturada. |
| `codexProtocol.ts` | Tradutor stateless Anthropic Messages ↔ OpenAI Responses: texto/imagem, inclusive screenshot em `function_call_output`, schemas de tools, `tool_choice`, `tool_use`/`tool_result`, esforço e tokens. `toCodexWireRequest` converte a família GPT-6 para Responses Lite: `additional_tools` + instrução em itens `developer`, sem `tools`/`instructions`/`max_output_tokens` no topo, `parallel_tool_calls: false`, reasoning em `all_turns` e `prompt_cache_key` por sessão. Mantém em memória os itens opacos de reasoning por `(accountId, sessionId, callId)` para replay seguro depois da execução da ferramenta; retomada sem cache usa transcrição segura. |
| `codexStream.ts` | Máquina de estados SSE Responses → Anthropic: blocos de texto, recusas e `tool_use`, argumentos JSON incrementais, chamadas paralelas, captura de reasoning/usage, validação de eventos/argumentos e exatamente um terminal por resposta. |
| `codexProxy.ts` | Servidor HTTP somente em loopback apontado por `ANTHROPIC_BASE_URL` nas sessões GPT. Autentica o CLI com segredo efêmero, vincula a sessão à conta e chama o backend Codex com OAuth. Para a família GPT-6 envia o header Responses Lite, `session-id`/`thread-id` e identidade de cliente `codex_cli_rs/0.146.0` com `version: 0.146.0`; isso corrige o 400 de alias/modelo e alinha o transporte Lite. Reutiliza token já renovado ou faz no máximo um refresh em 401, traduz o stream, sanitiza erros do upstream e propaga cancelamento. Não executa ferramentas: o Claude Code continua sendo o único harness/executor. **Consumo do plano ChatGPT:** `parseCodexRateLimitHeaders(headers)` lê os headers `x-codex-{primary,secondary}-used-percent/-window-minutes/-resets-in-seconds` (ou `-reset-after-seconds`) de cada resposta e devolve `RateLimitStatus[]` (`gpt_primary`/`gpt_secondary`); `onCodexRateLimit(listener)` registra o consumidor único (o `index.ts` reenvia como evento `rate-limit`). **Modo rápido do GPT:** o proxy é único no processo e compartilhado por todas as conversas, então o opt-in por conversa viaja no token de loopback — `parseProxyCredential` aceita o segredo exato **ou** o segredo + `FAST_MODE_TOKEN_SUFFIX` (`+fast`) e, no segundo caso, injeta `service_tier: 'priority'` (`CODEX_FAST_SERVICE_TIER`) no corpo. O sufixo não é credencial: segredo errado continua 401. |
| `claudeCli.ts` | `claudeCliPath()` resolve o **binário do CLI nativo do Claude Code** que o Agent SDK distribui como dependência opcional por plataforma (`@anthropic-ai/claude-agent-sdk-<plat>-<arch>`, `-musl` no Linux) via `require.resolve`; cacheia e lança se não achar. **Esse binário é diferente** da instalação global do `claude` (a que o comando `claude update` do sistema atualiza) — vive dentro do `node_modules` do projeto, e sua versão é fixada pela versão do `@anthropic-ai/claude-agent-sdk` no `package.json`. **Este projeto não usa o CLI global** para nada (login, sessões, tudo passa pelo binário empacotado) — rodar `claude update` no sistema **não tem efeito nenhum** aqui. |
| **Atualizar o CLI do Claude Code deste projeto** | ➜ `npm install @anthropic-ai/claude-agent-sdk@latest` (bump da dependência em `package.json`/`package-lock.json`, versão travada por `claudeCliPath()` acima). Depois: `npm run typecheck && npm test && npm run build` antes de considerar concluído. Esse é o único comando que atualiza o Claude **deste projeto** — o `claude update` do sistema é irrelevante para ele. |
| `store.ts` | **Persistência global por usuário** via `node:sqlite` (embutido): ponteiro `~/.agent-code/location.json` (só o caminho da pasta de cache) + `<escolhida>/agent-code/agent-code.db` (tabela `kv` key→JSON — config/UI/uso) + pasta `memories/` (Markdown da [memória persistente](ARQUITETURA.md#memória-persistente)). `initStore` (padrão `Documentos/agent-code` no 1º uso + migra `settings.json`), `kvGet`/`kvSet`, `getCacheInfo` (devolve `dir`/`dbPath`/`memoriesDir`), `setCacheDir` (cria a subpasta `agent-code`; se já houver db, só carrega — move `data/` inteira junto). **Conversas não vivem mais aqui** — ver `projectStore.ts`. `DB_NAME` é exportado só para `projectStore.ts` achar o banco legado na migração. |
| `projectStore.ts` | **Um banco SQLite por projeto**, só para conversas (`data/<slug>-<hash8>.db`, agrupadas por `cwd`) — em vez do blob único antigo. Sem dependência do módulo `electron` (`cacheDir` sempre vem por parâmetro), então é 100% testável contra um diretório temporário comum. `projectFileName(cwd)` gera o nome do arquivo (slug do nome da pasta + hash SHA-1 do caminho absoluto — evita colisão entre pastas de mesmo nome em locais diferentes; sem `cwd`, cai no bucket `sem-projeto.db`). `loadAllConversationRecords(cacheDir)` varre todo `.db` de `data/` e concatena (mesmo contrato de "carregar tudo"). `saveAllConversationRecords(cacheDir, list)` agrupa por projeto, regrava o arquivo de cada um e **apaga** o de qualquer projeto que não apareça mais na lista (sem "fantasma" ressurgindo). Migração automática e idempotente (`migrateLegacyConversations`, chamada por ambas): na 1ª vez que `data/` não existe, lê o blob antigo (`agentcode.conversations.v1` do `agent-code.db`), faz backup do banco inteiro (`agent-code.db.bak`, só uma vez), divide por projeto e **apaga a chave antiga** do banco global (`deleteLegacyConversationsKey`) — o `.bak` é o backup, não uma chave morta guardada pra sempre num banco que continua em uso. |
| `projectStore.test.ts` | Testes (Vitest, contra `mkdtempSync` — sem tocar a pasta de cache real): `projectFileName` estável e sem colisão entre pastas de mesmo nome; split/merge por projeto; apagar o arquivo de um projeto esvaziado; migração do blob legado preserva todas as conversas, faz o backup, **apaga** a chave antiga do banco global (o `.bak` fica intacto como backup), e é idempotente (rodar 2× não duplica). |
| `config.ts` | Lê/grava `AppConfig` na chave `config` do SQLite (`store.ts`) — antes era `settings.json`. Guarda a **API key da OpenAI exclusivamente para voz** (`openai`, com merge aninhado; modelos GPT nunca usam essa key/API), a **integração Ollama Cloud** (`ollama` = `{enabled, apiKey}`, com merge aninhado), "permitir tudo", o **token fixo do Android** (`remoteToken`) e `remoteEnabled`. `loadConfig`/`saveConfig`/`updateConfig` (merge sem clobber). |
| `attachments.ts` | Salva anexos **não-imagem** (Excel, PDF, zip, código…) em disco no main e devolve o caminho, para o agente abrir com `Read`/etc. (imagens seguem como blocos base64). |

## broker — relay multiusuário (VPS)

Projeto **Node separado** (`broker/`, próprio `package.json`, deps: `ws`; Docker) que roda na VPS e faz o acesso remoto **sem senha de VPS**: o PC disca por WebSocket e se registra pelo token; o celular conecta por HTTP e o broker roteia pelo `?token=`. **Stateless** (só o mapa token→conexão em memória; sem DB → sem backup).

| Arquivo | Responsabilidade |
|---------|------------------|
| `src/broker.js` | `createBroker({relayKey, pingIntervalMs, hostDeadMs, headTimeoutMs})`: HTTP (celular) + WS `/__relay` (PCs) na mesma porta; mapa `token→conexão`; relay HTTP↔WS com **SSE em streaming**; cookie `relay_token` (fallback); `RELAY_KEY` opcional. **Posse do token:** o `hello` leva `instanceId`; outro PC com o mesmo token recebe `busy` (o primeiro vence), o mesmo PC reconectando substitui a conexão velha. `sweep()` pinga e **derruba PC mudo** por mais de `HOST_DEAD_MS` (70 s); request sem `head` em `HEAD_TIMEOUT_MS` (60 s) vira **504**; corpo acima de 32 MB vira **413**; `ping` JSON do PC recebe `pong`. |
| `server.js` | Entrypoint (env `PORT`/`RELAY_KEY`; SIGINT/SIGTERM). |
| `test/broker.test.js` | Integração real (round-trip http↔ws, isolamento por token, SSE, POST com corpo). Config próprio em `vitest.config.mjs`. |
| `Dockerfile` / `docker-compose.yml` | Imagem `node:22-alpine`; expõe `127.0.0.1:8099` (só o Nginx fala); `env_file` `.env`+`.env-prod` (padrão do projeto). |
| `README.md` | Como rodar/deployar e o fluxo do relay. |

> Deploy: subir a pasta `broker/` pra VPS + `docker compose up -d --build`; o Nginx é configurado por `scripts/vps-remote-broker.sh` (proxy pro broker com upgrade de WebSocket + SSE).

## smartfone-remote — app do celular

Projeto **Capacitor** separado (próprio `package.json`/`package-lock.json`) que vira o APK do controle remoto. O cliente é `www/` (HTML/JS puro, servido em `/app` pelo PC e empacotado no APK).

| Arquivo | Responsabilidade |
|---------|------------------|
| `capacitor.config.json` | Config do Capacitor (id/nome do app, pasta `www`). |
| `package.json` | Deps do Capacitor (+ `@capacitor/assets` para os ícones) e scripts (`icons`, `assets`, `build:apk`). |
| `resources/` | **Arte do ícone/splash** do app (mesma faísca coral do desktop): `icon-only.png`, `icon-foreground.png`, `icon-background.png` (1024²) e `splash.png`/`splash-dark.png` (2732²). Geradas de `build/icon.svg`; consumidas por `@capacitor/assets generate --android` para criar todas as densidades de mipmap + o ícone adaptativo. |
| `scripts/make-icons.mjs` | Rasteriza `build/icon.svg` (via Playwright do projeto pai) nos assets de `resources/`. Rode da raiz do repo: `node smartfone-remote/scripts/make-icons.mjs`. |
| `scripts/build-apk.mjs` | Gera o APK: copia o `www/`, adiciona/atualiza a plataforma Android, **aplica o ícone** (`@capacitor/assets generate`, se houver `resources/`) e roda o Gradle (chamado por `remote:build-apk`). |
| `www/index.html` | Telas do app: pareamento (QR/manual, ícones SVG), overlay do scanner, e o chat (header com status pill, mensagens, composer com **anexo de imagem**, **barra de modelo/esforço** (`#model-bar` — dois `<select>` nativos acima do composer), bandeja de preview, **drawer de histórico** e **menu de sair**). |
| `www/app.js` | Lógica do cliente: parear, **auto-conectar** na última sessão, **auto-reconexão** do SSE com backoff + **wake lock**, histórico por projeto (drawer), abrir conversa (`/api/history` + SSE), enviar comando + **imagens** (base64), **markdown** das respostas (`mdToHtml`/`parseDownloads`, seguro por escape), **cards de ferramenta recolhidos/expansíveis** (`renderTool`/`describeTool`, estado em `state.openTools`), **scroll** preservado durante o streaming (`scheduleRender` + rAF), e **botões de download** (chip de `Write` entregável + marcador `[[download:]]` → `/api/file`). **Trocar modelo/esforço** (`renderModelBar`/`setModel`): seletores preenchidos do catálogo do `/api/state` (`models`/`modelEffort`/`effortLabels`), mostram o modelo/esforço atuais da conversa, POST `/api/set-model` na troca (otimista, o poll reconcilia); esforço some para modelo sem suporte (Ollama), ambos desabilitados enquanto a conversa está `busy`, e o rebuild é pulado se o usuário estiver com o dropdown aberto (activeElement). **Loading ao abrir um chat:** `loadHistory(convId, silent)` mostra "Carregando mensagens…" (`state.historyLoading`) quando `silent` é falso (abrir/trocar de chat — `selectConv`); um contador `historyReq` garante que só a resposta da chamada **mais recente** atualiza a tela (trocar de chat rápido não deixa o spinner grudado nem uma resposta antiga sobrescrever a atual). **Silencioso** (`silent: true`, mensagens continuam visíveis, sem o loading cheio): a ressincronização ao **(re)conectar** (`openEvents`/`es.onopen`) e o **pull-to-refresh** — puxar a lista a partir do topo (`onPullStart`/`onPullMove`/`onPullEnd`, touch e mouse) mostra "Puxe…" → "Solte para atualizar" (`PULL_THRESHOLD`) → "Atualizando…" na barra `#pull-refresh` (reaproveita o estilo de `#reconnect`) e recarrega a conversa inteira ao soltar. |
| `www/styles.css` | Tema escuro moderno (gradientes, status pill, bolhas com gradiente, drawer/popover animados): pareamento, scanner, chat, markdown (`.md`), cards de ferramenta, bandeja de imagens, botões de download. |
| `www/jsqr.js` | Biblioteca jsQR (decodifica o QR a partir dos frames da câmera). |
| `android/app/src/main/java/.../MainActivity.java` | `BridgeActivity` do Capacitor que salva na pasta Downloads os arquivos servidos pela ponte (`/api/file`) via **DownloadManager**. O caminho que de fato roda no app é o `@JavascriptInterface` **`AgentDownload.enqueue(url, nome)`**, chamado direto pelo `www/app.js`: o `setDownloadListener` sozinho **nunca era alcançado** — o Capacitor externaliza navegação para outro host, então o `<a download>` abria o Chrome e nada era salvo (medido no emulador). Só enfileira URL `http(s)` terminando em `/api/file`, com o nome sanitizado. Gerenciado/reaplicado pelo `buildApk.ts` (o `android/` é gitignorado/regenerado); `MAIN_ACTIVITY_JAVA` é exportado para que essa fonte única possa ser materializada num projeto Android já gerado. |
| `README.md` | Como buildar/instalar o app remoto. |

## Tipos de dados

Principais formas (ver `src/shared/ipc.ts` e `src/renderer/src/types.ts`):

```ts
// Evento normalizado de chat (main → renderer)
type ChatEvent =
  | { kind: 'system'; sessionId: string; model: string; cwd: string; tools: string[] }
  | { kind: 'assistant-text'; id: string; text: string; final: boolean }
  | { kind: 'thinking'; id: string; text: string }
  | { kind: 'tool-use'; id: string; name: string; input: unknown; parentToolUseId: string | null }
  | { kind: 'tool-result'; id: string; toolUseId: string; isError: boolean; text: string }
  | { kind: 'result'; id: string; isError: boolean; text: string; durationMs: number; costUsd?: number; contextTokens?: number; usage?: TokenUsage }
  | { kind: 'status'; id: string; text: string }
  | { kind: 'error'; id: string; text: string }
  | { kind: 'rate-limit'; limits: RateLimitStatus }   // uso da CONTA (5h/semana) — global, nunca vira bolha de chat

interface StartAgentOptions { convId: string; cwd: string; model?: string; skipPermissions?: boolean; resume?: string; effort?: string }
interface AgentEventMsg { convId: string; event: ChatEvent }            // main → renderer (cada evento marcado com a conversa)
interface PermissionRequestMsg { convId: string; req: PermissionRequest }
interface PermissionExpiredMsg { convId: string; id: string }           // main → renderer: pendência expirou (7 min) → fecha o modal
interface AndroidProgressMsg { convId: string; line: string }           // progresso do boot/instalação do Android
interface PermissionRequest { id: string; toolName: string; input: Record<string, unknown>; questions?: AskQuestion[]; deadline?: number }  // deadline = epoch ms p/ auto-resolver
interface PermissionResponse { id: string; behavior: 'allow' | 'deny'; always?: boolean; message?: string; answers?: QuestionAnswer[] }

// Pergunta interativa do agente (AskUserQuestion)
interface AskQuestionOption { label: string; description: string }
interface AskQuestion { header: string; question: string; multiSelect: boolean; options: AskQuestionOption[] }
interface QuestionAnswer { header: string; question: string; selected: string[] }  // picks + texto livre ("Outro")

// Abas de preview
type TabKind = 'web' | 'android' | 'iphone' | 'file'
interface TabInfo { id: string; kind: TabKind; title: string; url: string; active: boolean }
function tabName(t: { kind: TabKind; title: string; url: string }): string   // ex.: "web - Google" / "android - <app>"

interface BrowserState {
  url: string; title: string; loading: boolean; canGoBack: boolean; canGoForward: boolean; launched: boolean
  tabs: TabInfo[]                                  // todas as abas (ordem da barra)
  androidSize?: { width: number; height: number } // tamanho atual da aba Android ativa
}
interface BrowserFrame { data: string; width: number; height: number; mime?: 'image/jpeg' | 'image/png' }  // web = JPEG, Android = PNG
type BrowserInput =
  | { type: 'move'; nx: number; ny: number }
  | { type: 'click'; nx: number; ny: number; button: 'left' | 'right' | 'middle' }
  | { type: 'wheel'; nx: number; ny: number; dx: number; dy: number }
  | { type: 'key'; key: string; text?: string }
interface PickedElement { selector: string; tagName: string; id: string; classes: string; text: string; html: string; url: string; tabId: string; tabName: string }
interface ImageAttachment { mediaType: string; data: string }   // data = base64 sem prefixo
interface FileAttachment { name: string; mediaType: string; data: string }  // anexo não-imagem (base64; o main salva em disco e passa o caminho ao agente)

// Configuração e pasta de dados (por usuário)

interface OpenAiConfig { apiKey: string; voice: string; speed: number }   // voz no chat (TTS + transcrição)
interface OllamaConfig { enabled: boolean; apiKey: string }   // Ollama Cloud (modelos via API compatível com a Anthropic)
const OLLAMA_BASE_URL = 'https://ollama.com'                  // ANTHROPIC_BASE_URL no modo Ollama
function isOllamaModel(model?: string): boolean               // true se o id termina em ':cloud'
const CONTEXT_LIMITS: Record<string, number>                  // janela de contexto REAL por modelo (Opus/Sonnet/Fable=1M, Haiku=200K; Ollama: Nemotron 3 Ultra=256K, gpt-oss=128K, DeepSeek V4 Pro=1M, GLM-5.3 (e Flash)=1M, Kimi K3=1M — verificados contra os specs de cada modelo)
const DEFAULT_CONTEXT_LIMIT = 200_000                          // fallback p/ modelo fora do mapa
function contextLimitFor(model?: string): number              // limite do modelo (cai no DEFAULT) — denominador da barra de contexto
function modelSupportsVision(model?: string): boolean          // Claude sempre true; Ollama só true p/ OLLAMA_VISION_MODELS (hoje só kimi-k3:cloud, multimodal nativo) — o resto passa pelo vision_fallback_router
type FastModeTransport = 'anthropic-setting' | 'codex-priority'
function fastModeTransport(model?: string): FastModeTransport | null  // COMO pedir modo rápido: settings.fastMode (Opus 5/4.8) x service_tier:'priority' no corpo Codex (GPT-6). Mandar o canal errado é HTTP 400, não no-op
function modelSupportsFastMode(model?: string): boolean         // = fastModeTransport(model) !== null — gate do toggle na UI
interface AppConfig { openai: OpenAiConfig; ollama: OllamaConfig; skipPermissions: boolean; remoteToken: string; remoteEnabled: boolean }
interface CacheInfo { dir: string; dbPath: string; memoriesDir: string }   // …/agent-code/{agent-code.db, memories/}

// Download pelo chat
function isDownloadableFile(path: string): boolean                 // extensão entregável (DOWNLOADABLE_EXTS)
function parseDownloads(text: string): { clean: string; paths: string[] }  // remove [[download:PATH]] e devolve os caminhos

type DeviceType = 'phone' | 'tablet'
interface AndroidDeviceModel { id: string; name: string; type: DeviceType; width: number; height: number; dpi: number; year: number }

// Controle remoto (ponte LAN com o celular)
interface RemoteInfo { running: boolean; url: string; ip: string; port: number; token: string; clients: number }

interface RemoteStatePayload { conversations: RemoteConversation[] }

  result?: { isError: boolean; text: string }

  tokens: { context: number; output: number; cost: number }
  createdAt: number; updatedAt: number
}
```
